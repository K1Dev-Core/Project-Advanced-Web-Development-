# Dev tools — สร้างข้อมูลทดสอบ

เปลี่ยนไอคอนลอย Dev tools เป็นเครื่องมือสร้างข้อมูลธุรกิจผ่าน backend ของแอปแทนตัวตรวจ API/ตัวอย่าง UI

## การใช้งาน

1. เข้าสู่ระบบเจ้าของร้าน แล้วกดไอคอนประกายมุมขวาล่าง
2. เลือกชุดพร้อมลอง ลูกค้า รายการสั่งอาหาร หรือไรเดอร์
3. กำหนดจำนวน วันที่จัดส่ง และรัศมีรอบร้านตามประเภทข้อมูล ตรวจสรุปแล้วกด **สร้างข้อมูลทดสอบ**
4. ดูจำนวนที่สำเร็จและ seed แล้วเปิดหน้ารายการที่ต้องการ เมื่อเปิดรายการส่งจะใช้วันที่ที่เลือกสร้างไว้

## API และข้อมูล

| ประเภท | API | ค่าหลัก |
| --- | --- | --- |
| ลูกค้า | POST /simulations/customers | count 1–500, radiusKm 0.2–50, minRadiusKm 0.2, seed ไม่บังคับ |
| ไรเดอร์ | POST /simulations/riders | count 1–100, seed ไม่บังคับ |
| รายการอาหาร | POST /simulations/orders | count 1–500, deliveryDate แบบ ISO, clearExisting=false, ensureCustomers=true, uniqueCustomers=true |
| ชุดพร้อมลอง | เรียกสาม endpoint ตามลำดับ | ลูกค้า → ไรเดอร์ → รายการอาหาร |

ใช้ JWT เจ้าของร้านและ backend เดียวกับแอป สร้างข้อมูลลงฐานข้อมูลจริง ลูกค้าและรายการอาหารใช้ simulated=true และมีป้ายข้อมูลทดสอบในตาราง ไรเดอร์ใช้โมเดลเดิมที่ไม่มี flag นี้ ราคา/จำนวนกล่องสูงสุดอ้างอิงการตั้งค่าร้าน backend สร้างลูกค้าเพิ่มหากจำนวนยังไม่พอสำหรับรายการอาหาร

ปุ่มสร้างซ้ำและปิดหน้าต่างถูกปิดระหว่างทำงาน ขั้นตอนที่สำเร็จแสดงแยกไว้ หากขั้นตอนต่อไปล้มเหลวจะหยุดและเก็บผลส่วนที่สำเร็จ ไม่ย้อนลบข้อมูลและไม่ retry อัตโนมัติ หากขาดการเชื่อมต่อ ผู้ใช้ต้องตรวจหน้ารายการก่อนสร้างซ้ำเพราะ server อาจประมวลผลเสร็จแล้ว

## Test cases

- ผู้ไม่เข้าสู่ระบบเห็นทางเข้าสู่ระบบและไม่สามารถเรียกสร้างข้อมูลได้
- ชุดข้อมูลส่ง POST ทั้งสาม endpoint ตามลำดับ พร้อม Bearer token และชนิดค่าที่ถูกต้อง
- clearExisting=false ไม่ล้างรายการเดิม, seed ส่งเมื่อระบุ, date เป็น yyyy-MM-dd
- กรอกเกินขอบเขตไม่เรียก API, ป้องกัน double-submit, Escape/ปุ่มปิดใช้ไม่ได้ระหว่างบันทึก
- เมื่อไรเดอร์สร้างไม่สำเร็จ ยังแสดงจำนวนลูกค้าที่สำเร็จและไม่ส่งคำขอสร้าง orders ต่อ
- หลังปิดรีเฟรชรายการปัจจุบัน และเปิดรายการส่งพร้อมวันที่ที่สร้าง
- หน้าต่างบนจอ 320px ไม่ล้นขอบและเลื่อนได้
- ปฏิทินภายใน Dev dialog ใช้ได้ ปิดด้วย Escape แล้วเปิด dropdown หน้าหลักต่อได้
- Local integration สร้างลูกค้า 2 คน ไรเดอร์ 1 คน รายการอาหาร 3 รายการ ตรวจค่าจาก MySQL/API และแสดงในหน้ารายการจริง รวมตรวจ POST ที่ไม่มี JWT ได้ 401

Local integration ใช้ localhost:3000 กับ songsook_local พอร์ต 33307 เท่านั้น เก็บ ID ก่อนเริ่มและลบเฉพาะข้อมูลใหม่ที่เกิดในรอบทดสอบ ไม่มีการสร้างข้อมูลใน production ระหว่างตรวจ

- Initial bundle: 509.59 kB raw / 109.18 kB estimated transfer มี warning budget 500 kB เกิน 9.59 kB และ Leaflet CommonJS เดิม
